# 长程任务助手 · Nightshift

Windows 本地托盘应用。把 Codex 开发任务拆成可恢复的阶段，等待实际额度刷新，并优先为白天保留额度。

这是 **0.2.0**：调度策略、持久化、协议客户端、对话回复和阻塞处理已有自动化测试，演示界面已通过 Electron 冒烟检查。ChatGPT 登录、真实任务和真实额度跨窗口续跑尚未完成实机验证。首次使用请先运行演示，再用独立项目的小任务验证。

## 直接启动

打开 `release/Nightshift-Windows-x64/Nightshift.exe`，或双击 `Start.cmd`。此目录是完整便携包，不能只复制 EXE。

体验模拟任务：双击同目录的 `Start-Demo.cmd`。演示使用单独的数据目录，不调用模型、不消耗额度、不修改项目；跳过夜间时段等待，模拟每阶段消耗，触及上午保留线后暂停。

关闭窗口会隐藏到系统托盘。托盘菜单可打开主界面、暂停、停止并保存总结，或退出应用。退出会保存恢复检查点；下次启动需要手动继续，防止重复执行。

## 第一次真实运行

1. 打开「运行策略」，连接 Codex。程序会尝试检测已安装的 Codex 桌面端；找不到时，手动选择官方 `codex.exe`。
2. 如果未登录，点击「使用 ChatGPT 登录」，在浏览器完成登录。应用通过官方 App Server 使用登录状态，不读取或保存账号密码，不提供 API Key 自动付费回退。
3. 确认界面能读取完整的 5h、周额度及重置时间。缺失、过期或不认识的窗口不会按零用量处理，真实任务会暂停。
4. 选择一个本地项目目录，建议使用独立 Git 分支。填写明确的目标和可验证的验收条件。
5. 点击「开启夜间任务」。白天开启会等待下一个夜间时段。到起床时间后自动暂停交接，不会在你工作时抢跑下一轮。
6. 早上查看阶段记录、代码修改及验证结果，可导出 Markdown 报告。

## 对话、选择和阻塞

- 左侧「任务对话」读取本应用创建的 Codex 会话历史，包括发送给 Codex 的内容、可见回复、命令与输出、文件变更。暂停后仍可查看；需要连接本机 Codex App Server，但读取历史不要求有剩余额度。
- 暂停或阻塞后可在同一会话直接发送回复。当前回复完成后不会自动重启夜间调度。
- 命令、文件和权限请求会展示具体内容，等待你允许本次或拒绝；选择题可在卡片中回答。未得到明确选择不会自动批准。关闭应用会取消待处理请求并保存检查点。
- 阶段报告阻塞或没有实质进展时，立即停止自动开启新阶段。处理条件后点击「已处理阻塞」，再手动继续夜间调度。
- 运行策略中的阅读字体可选 14、16、18、20px，默认 16px；应用会保存偏好。
- 本应用使用独立的 Codex 运行目录，Codex 桌面项目列表不一定显示这些会话。请在本应用「任务对话」中查看和回复。

需要电脑保持开机、联网，Codex 登录有效。可选择运行期间阻止自动睡眠，屏幕仍可关闭；主动休眠、合盖或关机可能中断任务。

## 默认额度策略

| 设置 | 默认值 |
| --- | --- |
| 夜间开始 | 23:00 |
| 起床交接 | 10:00 |
| 目标刷新 | 起床后 1 小时，即 11:00 |
| 目标新窗口开启 | 06:00，取决于旧窗口是否已结束 |
| 上午保留 | 50% 的 5h 额度 |
| 周额度保留 | 30% |
| 提前缓冲 | 7 个百分点 |
| 普通夜间窗口保留 | 8% + 缓冲 |
| 每阶段目标时长 | 8 分钟 |
| 额度轮询 | 60 秒，另接收服务端更新通知 |

上午窗口剩余 57% 时触发保护；周额度剩余 37% 时停止任务。保留线是调度目标，不是服务端硬预算：单次请求、用量更新延迟和同账户的其他会话都可能跨过保护线。不能保证任意任务都能用 50% 额度工作到刷新。

已有额度窗口不能强行重启。若旧窗口在凌晨 04:00 结束，且服务端仍返回已结束窗口，调度器会等到目标 06:00 再尝试恢复，避免过早开启新窗口；若旧窗口结束时间晚于目标，则展示真实时间并按实际窗口保护。服务端明确的 5h 刷新时间过后，必须先重新读取额度，才允许有界的恢复尝试；仍被限额时保存进度并退避，最多连续失败三次。

达到周额度保护线、起床交接、手动暂停、权限请求、无进展或程序重启后，均不会自动恢复。需要用户检查后重新开启。演示跳过夜间等待，但真实执行严格遵守运行时段。

## 任务执行与恢复

- 每轮只执行一个小阶段，要求输出进展、真实验证、下一步和是否完成。
- 按具体 thread ID 恢复本应用创建的任务，不使用「最近一次会话」。第一版不接管其他 Codex 窗口的现有聊天。
- SQLite WAL 保存任务、设置、日志、差异和检查点；阶段结果与任务状态在同一事务提交。
- 中断时保存已有证据，无额度也能生成报告，不依赖最后一次模型总结。
- 工作区沙箱限制写入范围；权限申请、交互请求会取消当前操作并暂停。不会自动批准提权。任务默认不开放网络，可在设置中开启沙箱网络访问。
- 任一阶段报告无实质进展即暂停。阶段超过目标时间时先要求收尾，45 秒后仍未结束则中断并等待检查。
- 本应用只能调度自己的后台任务，不能冻结同一账号的其他 Codex 会话或为账户增加额度。

数据保存在 Electron 的用户数据目录。演示数据和真实数据隔离。用户数据可能包含代码 diff、任务目标及日志，应按本地项目数据管理。源码及便携包不包含登录信息或运行数据。

## 从源码运行

要求 Windows x64、Node.js 22.18+、Electron 42.3.0，以及真实运行时的官方 Codex。

```powershell
npm install
npm start
# 演示模式
npm run demo
# 自动化测试
npm test
```

如本机有 Electron 42.3.0 的官方缓存 ZIP，可离线准备：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/setup-offline.ps1
# 或传入明确的 ZIP 路径
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/setup-offline.ps1 -ElectronZip C:\Downloads\electron-v42.3.0-win32-x64.zip
npm run package
```

构建使用 Node 自带 TypeScript 转换器，不依赖在线下载构建工具。`npm run smoke` 是原生 Electron 冒烟检查入口，会操作演示任务并输出截图与结果；已在本机通过。`node scripts/probe.mjs` 可只检查 Codex 握手、账户类型、额度可读性和模型列表，不发送模型任务；已在本机通过。

## 源码结构

- `src/shared/policy.ts`：作息计算、窗口识别、额度决策及配置校验。
- `src/main/scheduler.ts`：阶段状态机、交接、恢复及保护控制。
- `src/main/codex.ts` / `rpc.ts`：官方 App Server 的 stdio JSON-RPC 客户端。
- `src/main/store.ts`：SQLite 本地持久化。
- `src/main/main.ts` / `preload.cts`：托盘、窗口、最小 IPC 桥接。
- `src/renderer/`：中文界面。
- `tests/`：额度边界、恢复、权限及协议测试。

参考：[Codex App Server](https://developers.openai.com/codex/app-server/)、[额度机制](https://help.openai.com/en/articles/20001516-managing-usage-with-gpt-6-astra-in-work-and-codex)。
